# Mod Loader для reVC_test_fix

Результаты для Remastered Interface, VC Weapon Wheel и Ferrari из присланных
архивов: [ModCompatibility.md](ModCompatibility.md). Ресурсные моды и
экспериментальные оригинальные ASI используют разные пути загрузки.

Отдельная экспериментальная работа над ABI неизменённых оригинальных ASI
описана в [LegacyASI.md](LegacyASI.md). Это не часть ресурсного Mod Loader;
общая совместимость сторонних ASI пока не реализована.

Поддержка предназначена для Windows x86/x64 и всех графических бэкендов проекта: D3D9, OpenGL и WGPU. Игра загружает `modloader.asi` напрямую: отдельный ASI Loader (`dinput8.dll`, `d3d8.dll` и т. п.) не нужен. Без Mod Loader игра продолжает использовать штатную загрузку ресурсов. Linux-сборка не загружает Windows DLL и сохраняет прежний механизм ресурсов.

Используются исходники [Cowboy-69/modloader](https://github.com/Cowboy-69/modloader/tree/76c127e983069bcb1308b198c11ce8b81147b0bc), commit `76c127e983069bcb1308b198c11ce8b81147b0bc`, с локальным `utils/modloader/revc-compat.patch`. Пример подключения к reVC: [gta-extended-2025, commit 6152026](https://github.com/x87/gta-extended-2025/commit/615202600c578fa840d4779170f77aba1b0f2219). Патч согласует ABI, исправляет размер streaming-info x64, добавляет безопасную подготовку/остановку потока перед выгрузкой DLL и устраняет обращение к уничтоженным профилям при завершении работы. Готовые сторонние ASI из интернета не скачиваются.

## Установка

В GitHub Actions отдельный workflow `reVC native Mod Loader` собирает пакеты `reVC_ModLoader_Release_x64` и `reVC_ModLoader_Release_x86`. Они дополняют обычный артефакт игры той же разрядности; повторно скачивать Mod Loader для каждого рендерера или Debug/Release не нужно.

Выберите пакет той же разрядности, что и `reVC.exe` (обычно x64), закройте игру и скопируйте содержимое `build/modloader-dist/x64/` рядом с ней:

```text
reVC.exe
modloader.asi
modloader/
  .data/
    plugins/gta3/       # семь DLL из нашего пакета
    LICENSE
    licenses/
    reVC-build.json     # источник, commit, патч и SHA-256 бинарников
  MyVehicle/
    infernus.dff
    infernus.txd
```

Каждый мод размещайте в отдельной подпапке `modloader/`; базовые IMG/DIR и файлы игры перезаписывать не нужно. Для отключения мода перенесите его папку за пределы `modloader/` при закрытой игре. Для отключения всей системы уберите `modloader.asi`. Пользовательские профили и приоритеты настраиваются через `modloader/modloader.ini`; документация и шаблоны `*.ini.0` входят в пакет. При обновлении не удаляйте свои моды и действующие `.ini`.

Не смешивайте x86/x64 и не заменяйте только одну DLL из старой установки. Используйте ASI и все семь плагинов из одного пакета. Старые сборки без совместимого callback ABI отключаются игрой с записью в журнал. Лог Mod Loader — `modloader/modloader.log`.

## Сборка пакета из исходников

Нужны Windows, Git и Visual Studio 2022 / Build Tools с компонентом C++ x86/x64 и Windows SDK. Premake уже находится в корне этого репозитория; зависимости Mod Loader включены в его закреплённые исходники. Первое клонирование требует интернет. Сборка `std.data` тяжёлая и может занять несколько минут; по умолчанию используются два параллельных задания.

Из корня проекта:

```powershell
# Собрать и упаковать x64 Release; для обеих разрядностей: -Architecture All
powershell -NoProfile -ExecutionPolicy Bypass -File .\utils\modloader\build.ps1 -Architecture x64

# Только упаковать уже собранные файлы, без повторной компиляции
powershell -NoProfile -ExecutionPolicy Bypass -File .\utils\modloader\build.ps1 -Architecture x64 -PackageOnly

# Установить готовый пакет в конкретную копию игры
powershell -NoProfile -ExecutionPolicy Bypass -File .\utils\modloader\build.ps1 -Architecture x64 -PackageOnly -InstallDirectory 'D:\Games\Vice City'
```

Исходники сохраняются в игнорируемом `build/modloader-upstream/`, пакет — в `build/modloader-dist/<arch>/`. Скрипт проверяет commit и точное соответствие локальному патчу; чужие изменения не сбрасывает. Для кириллицы в пути временно занимает свободную букву N:–Z: и освобождает её после сборки; существующие подключения, включая M:, не затрагиваются. Можно указать `-SourceDirectory`, `-OutputDirectory`, `-MSBuildPath` и `-Jobs`.

Подготовку исходников можно проверить отдельно, без компилятора и запуска DLL:

```powershell
.\utils\modloader\build.ps1 -PrepareOnly
.\utils\modloader\test-source-patch.ps1
```

Первый вызов при необходимости скачивает закреплённые исходники и применяет патч. Второй использует только их локальную Git-копию: проверяет LF/CRLF патча при обоих значениях `core.autocrlf`, повторный запуск и сохранность посторонних изменений. Тестовые копии остаются в `build/modloader-source-tests/`. Перед применением патча сборщик нормализует только временную копию самого `.patch` в LF; настройки Git и переводы строк исходников не меняет. Это сохраняет корректность хунков для файлов без завершающего перевода строки. В Actions эти проверки выполняются перед сборкой обеих разрядностей.

Это повторяемая сборка закреплённых исходников, а не обещание побитово одинаковых DLL: результат также зависит от версии MSVC/SDK и встроенной upstream-даты версии. `-PackageOnly` проверяет PE-разрядность и исходный патч, но предполагает, что существующие бинарники действительно были собраны из этих исходников. Скрипт не запускает собранные ASI/DLL.

Отключение bridge при сборке самой игры:

```powershell
cmake -S . -B build/game-no-modloader -DREVC_WITH_MODLOADER=OFF
.\premake5.exe --no-modloader vs2022
```

## Ресурсы и ограничения

Пакет содержит только `std.fx`, `std.stream`, `std.data`, `std.text`, `std.scm`, `std.sprites`, `std.movies`. Подключены замены streaming DFF/TXD/COL/IFP и IMG/DIR, IDE/IPL, поддерживаемых DAT/CFG (включая handling, carcols, timecycle), GXT, `main.scm`, шрифтов/HUD/частиц и других предусмотренных fork-ом ресурсов. Форматы должны быть совместимы с Vice City и выбранным рендерером. Поддержка точки загрузки не означает совместимость любого мода; проверяйте его требования.

Это не загрузчик оригинальных GTA ASI, CLEO или скриптов/патчей, привязанных к адресам оригинального `gta-vc.exe`. `std.asi` не включён; SA-специфичные `std.bank` и `std.tracks` тоже не поставляются. Не добавляйте оригинальные DLL-плагины в `.data/plugins`: они могут иметь другой ABI. Linux/Wine, FXT-инъекции и произвольные моды оригинальной игры не получают автоматической совместимости.

Лимиты моделей, текстурных/коллизионных/анимационных слотов проекта не увеличиваются: крупные аддоны могут требовать отдельной адаптации. Не все ресурсы допускают горячую перезагрузку — для надёжного результата устанавливайте моды при закрытой игре; после смены `main.scm` начинайте новую игру. Совместимость конкретного набора модов проверяйте отдельно. Права на исходные ресурсы и моды остаются у их авторов.
