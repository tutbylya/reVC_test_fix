# Экспериментальный ABI оригинальных ASI

Обновление 7 ноября: добавлен профиль неизменённого VC Weapon Wheel из
конкретного архива пользователя; открытие колеса подтверждено пользователем.
Дополнительные проверки и ограничения: [ModCompatibility.md](ModCompatibility.md).
В частности, это не поддержка произвольных ASI на x64/WGPU или Linux.

Статус: ограниченный ABI Vice City 1.0 EN расширен под неизменённый Amazing
Snapshot VC v1.1. **Проверка этого мода в настоящей игре ещё не завершена**.
Компиляция, статический аудит и собственные fixtures её не заменяют. Это не
общая совместимость со всеми ASI оригинальной игры.

Это отдельная Windows MSVC x86-сборка D3D9/OpenGL. Обычные x64/WGPU и native
Linux-сборки этот код не включают. Windows x86 DLL нельзя исполнять внутри x64
процесса; ресурсный Mod Loader остаётся независимой системой.

## Общий принцип

Код ASI не переписывается и не перекомпилируется под reVC. Слой предоставляет
небольшую общую часть адресного ABI Vice City 1.0 EN: оригинальные адреса,
патчируемые `CALL`-точки и адаптеры вызовов. Расширять нужно общую таблицу ABI,
но каждый бинарник всё равно требует проверки совместимости.

| Доступная часть профиля | Реализация |
| --- | --- |
| Четыре события | Init RW `0x4A5B6B`, Shutdown RW `0x4A5B8E`, Game Process `0x4A5DA0`, Drawing `0x4A61D6`; `CALL rel32` + `RET`, поддержка цепочек хуков |
| 17 функций | Suspend/Resume/Stop/user pause/cycles/slow motion таймера; установка/сохранение/восстановление часов и запросы времени; ForceWeather/ForceWeatherNow/ReleaseWeather; SetFOV |
| 43 скалярных поля | Часть CTimer, CClock, CWeather, CDraw и флагов CHud; точный список — `globals` в `src/extras/legacy_asi.cpp` |
| Определение VC 1.0 старым SDK | Четырёхбайтовый маркер `0x53E58955` по `0x667BF0`, не оригинальный исполняемый код |
| Объекты | Необходимые поля оригинальных CCamera/CCam, CPad, мыши и меню; шесть методов камеры и GetPad; прокси позиции FindPlayerEntity |
| RenderWare/UI/звук | Представления framebuffer/raster/image, четыре RwImage API с реальными пикселями, используемые CFont API и PlayFrontEndSound |

Адреса проверены по [Plugin-SDK commit
15f15b60bbf74c106e1b496ff92c98764abf4605](https://github.com/DK22Pac/plugin-sdk/tree/15f15b60bbf74c106e1b496ff92c98764abf4605):
`plugin_vc/game_vc/{CTimer,CClock,CWeather,CDraw,CHud}.cpp`,
`shared/Events.h`, `shared/GameVersion.cpp`.

## Совместимый запускатель

Пакет содержит три соседних файла:

| Файл | Назначение |
| --- | --- |
| `reVC.exe` | Запускатель одного собственного дочернего процесса |
| `reVC-game.exe` | Маленький bootstrap с фиксированной базой и собственной секцией `.compat` |
| `reVC-core.dll` | Игровой код, загружаемый обычным Windows DLL loader |

Запускайте `reVC.exe`, не bootstrap напрямую. Запускатель создаёт только
соседний проверенный `reVC-game.exe`. Этот маленький экспериментальный EXE
собирается с `/BASE:0x400000 /FIXED /DYNAMICBASE:NO`: его образ занимает
канонические адреса силами Windows loader ещё до запуска первого потока.
Нужные оригинальные адреса находятся внутри его выделенной zero-filled
секции `.compat`, изначально RW и не исполняемой. Больше не требуется пытаться
зарезервировать эти адреса через VirtualAlloc после начала загрузки процесса.

Bootstrap передаёт ядру право использования собственной секции ровно один раз.
Ядро проверяет фактическую базу, тип MEM_IMAGE, границы и атрибуты `.compat`,
отсутствие пересечений с native-секциями и возможности запускателя. Записи и
изменения защиты разрешены только внутри `.compat`; настоящие заголовки и
native-секции не становятся частью изменяемого ABI-диапазона. Чужая память не
освобождается и не перезаписывается; поверх неё ничего не резервируется.
Произвольный путь EXE/PID запускатель не принимает.

Это осознанный компромисс отдельного opt-in bootstrap: **ASLR его главного
образа отключён**. ASLR ядра `reVC-core.dll`, зависимых DLL и обычных сборок не
меняется; DEP не отключается. Системные настройки защиты не изменяются.
Если обязательная политика ASLR или занятый адрес не позволяют загрузить
фиксированный образ, запуск должен завершиться отказом. Обхода политики,
освобождения чужих выделений или повторов «до удачи» нет.

В игровой сборке с каноническим главным образом (capability 2) ASI загружается
обычным `LoadLibraryEx`: `GetModuleHandle(NULL)` уже возвращает настоящую базу
`0x400000`. Здесь **нет отладочного подключения, подмены IAT или TLS callbacks**.

Отдельный инфраструктурный source-fixture (capability 1) сохраняет альтернативу
для private-арены и высокобазного тестового EXE: его запускатель подключается
только к собственному дочернему процессу и добавляет нативный TLS callback до
конструкторов ASI, сохраняя существующие callbacks. Он меняет поддержанные
импорты идентификации только этого ASI. Это проверка другого пути загрузчика,
не описание способа запуска текущей игровой сборки.

Windows по-прежнему выполняет загрузку импортов, static TLS, SEH, CRT и
DllMain. Реальный главный модуль, его PE-заголовки, AEP, PEB и список DLL не
подменяются. SDK читает каноническую базу реального bootstrap и маркер версии
по `0x667BF0` в `.compat`. Отдельный AEP-detector найденного v1.1 носит
информационный характер в проверенном пути: его результат не используется
обёрткой адресов. Это не повод патчить настоящую точку входа и не гарантия
совместимости остальных версий injector. ASI на диске не патчатся и не
перекомпилируются.

В поддержанном ABI-диапазоне `.compat` страницы адаптеров финализируются RX,
данные RW, маркер R, неиспользуемые страницы — NOACCESS. Постоянных RWX-страниц не нужно.
Промежутки используемой страницы нельзя защитить с точностью до отдельного
поля. Это **не песочница**.

Объекты — отдельные согласованные копии, не указатели на native-классы
reVC/librw под видом оригинальных структур. Неудачное чтение framebuffer,
например при потерянном устройстве, должно возвращать ошибку снимка, а не
фиктивный успех.

## Существенные ограничения

- Подготовка SDK-идентичности реализована по аудиту точного Amazing Snapshot
  v1.1 и проверена на собственном fixture, но его реальная игровая проверка
  ещё ожидается. Работа любой версии Plugin-SDK/injector не гарантируется;
  настоящий PE-заголовок bootstrap не заменяет полный оригинальный EXE.
- Прочие объектные поля, пулы, vtables, D3D-интерфейсы, дополнительные игровые
  функции, произвольные патчи кода и signature scanning оригинального образа
  не реализованы. Прокси сущности предоставляет позицию, не полный объект.
- Синхронизация скаляров и объектов выполняется на главном потоке вокруг поддержанных
  событий/API. Асинхронные обращения из потоков ASI не поддерживаются: возможны
  гонки и потеря записей. Сравнение с предыдущим снимком сохраняет изменения
  native-функций, вызванных из обработчика ASI.
- Заведомо опасные значения отклоняются: NaN/Inf, неверные bool, нулевой делитель
  часов, некорректные часы/минуты/секунды и индексы погоды, отрицательные скорости
  времени, недопустимые FOV/aspect/clip. В прототипе time scale ограничен 0–100,
  time step — 0–1000; это также ограничивает совместимость.
- Успешная загрузка DLL означает только выполнение её DllMain, не работу мода.
  Неподдержанный ASI может вызвать вылет, повреждение состояния или выполнить
  произвольный код с правами пользователя. Хеш проверяет идентичность ASI, а не
  его безопасность и не зависимые DLL.

Реальная широкая совместимость требует дальнейшего покрытия общих объектных
и RenderWare API и проверяемой матрицы конкретных неизменённых бинарников.
Успешная загрузка одного мода не означает поддержку остальных.

## Сборка прототипа

В отдельном каталоге проекта с ASCII-путём (Premake плохо обрабатывает кириллицу):

```powershell
.\premake5.exe --with-librw --with-legacy-asi --no-git-hash vs2022
msbuild build/legacy-asi/reVC-legacy-asi.sln /m:1 /p:Configuration=Release /p:Platform=win-x86-librw_d3d9-oal
# Либо Platform=win-x86-librw_gl3_glfw-oal
```

Выход: три файла в `bin/<platform>-legacy/Release/`. Объекты, librw и решение не
перезаписывают обычные сборки. Установочный путь из `GTA_VC_RE_DIR` намеренно
игнорируется. Пакет не устанавливает моды и не запускает игру автоматически.

Для CMake есть default-OFF `-DREVC_WITH_LEGACY_ASI=ON`: требуется отдельный
MSVC Win32 build directory, OAL и D3D9 либо GL3/GLFW. Неподдержанные платформы и
архитектуры отвергаются при конфигурации. WGPU x86 в текущих зависимостях нет.
Выход CMake — `bin/legacy-asi/` внутри build directory, для multi-config
генератора с дополнительным подкаталогом конфигурации.

## Явное включение проверенного бинарника

Используйте отдельную тестовую копию с полноценными игровыми данными и x86
звуковыми DLL. Не копируйте экспериментальный EXE поверх рабочей установки.
Загрузчик не сканирует все `.asi` рядом с игрой или в ресурсном `modloader/`.

```text
reVC.exe
reVC-game.exe
reVC-core.dll
legacy-asi/
  enabled.ini
  AmazingSnapshot.VC.asi
  AmazingSnapshot.ini
```

`enabled.ini` — UTF-8, максимум 32 записи. Пример синтаксиса:

```ini
[Modules]
AmazingSnapshot.VC.asi=1274308B5A1EE936E3EC68AF8FC91034D2BD6DA5A6BFB99A77DDA7FA30A11B03
```

Хеш можно получить командой `Get-FileHash -Algorithm SHA256`. Совпавший хеш
**не подтверждает ABI-совместимость**. Не добавляйте неподдержанный мод только
потому, что известен его хеш. Отсутствующий или пустой список не загружает ASI.

Пример относится только к `AmazingSnapshot.VC.asi` размером 345600 байт из
[официального релиза v1.1](https://github.com/rockwave69/AmazingSnapshot/releases/tag/v1.1).
Позднейшие исходники автора, commit
`540e14bc26903e6cf20006c8912d2e78a00ff16c`, использованы как справка, но не
выдаются за точные исходники этого release-бинарника. Другой релиз требует
отдельного аудита. Для известного v1.1 загрузчик дополнительно требует
возможность pre-CRT подготовки от запускателя и подтверждение IAT-подготовки.

INI находится рядом с ASI. Его стандартные клавиши после загрузки сцены:
**Alt+V** — вход/выход из режима камеры, **F12** — снимок, F1 — помощь.
Ожидаемое место JPEG без PortableGTA — `Gallery` в пользовательских файлах
Vice City. Поддержка PortableGTA и его патчей этим слоем не заявляется.

Перед выполнением первой DLL проверяются синтаксис всего списка, плоские имена
без путей/дубликатов, PE32 x86 DLL и SHA-256 всех записей. Ошибка прекращает запуск
без выполнения перечисленных ASI. Файлы удерживаются открытыми без разрешения
на запись/удаление; зависимости ищутся безопасными Windows search flags без
глобального изменения путей. Загруженные модули не выгружаются/перезагружаются
на лету: произвольные хуки и потоки нельзя автоматически откатить безопасно.
Ошибка после начала загрузки также прекращает запуск, сохраняя уже живые
модули и их адреса до завершения процесса.

## Регрессии

```powershell
cmd /c utils\legacy-asi\tests\build-and-test.cmd --run
./utils/legacy-asi/tests/loader_tests.ps1 -Run
cmd /c utils\legacy-asi\launcher\build-and-probe.cmd --run
```

Создаются собственные x86 ASI без reVC-заголовков и импортов. Они работают с
фиксированными адресами VC, устанавливают цепочку из двух хуков и меняют
скаляр по оригинальному адресу. Проверяются коллизии, границы, защиты страниц,
результат native-вызова и восстановление хуков. Это проверка инфраструктуры,
**не свидетельство работоспособности сторонних модов**. Все результаты тестов
находятся в игнорируемом `build/legacy-asi-tests/`.

Без флагов запуска команды только компилируют собственные fixtures.
Launcher probe отдельно проверяет static TLS, сохранённый TLS callback,
статический C++-конструктор и DllMain: все должны увидеть каноническую
идентичность в правильном порядке, а настоящий главный модуль — остаться
неизменённым. Ожидаемая маска — **63**. Этот probe прошёл 6 ноября 2026 при
явно разрешённом запуске вне ограниченного tool runner; скачанный Amazing
Snapshot он не исполнял. Результаты — `build/legacy-asi-launcher-probe/`.

Ранее прошли 82 проверки адресов/хуков. Повторная регрессия загрузчика 7 ноября
2026 скомпилировала исходники с `/W4 /WX`, прошла 25 preflight/negative-сценариев
и остановилась до исполнения первого валидного fixture: runner уже занял
исходный диапазон, Windows error 487. Оставшиеся положительные сценарии не
считаются пройденными. Повторы «до удачной ASLR», отключение защит или
освобождение чужой памяти не применяются. Все семь legacy-TU отдельно прошли
x64-компиляцию с WGPU-флагами без legacy-макроса. Отдельный экспериментальный
workflow GitHub Actions выполняет регрессии; его запуск здесь не выполнялся.

Эти результаты подтверждают части инфраструктуры, но не весь новый
трёхфайловый игровой запуск и не сторонний мод. Проверка неизменённого Amazing
Snapshot в игре, включая движение камеры, JPEG, Alt+Tab, восстановление
состояния и выход, остаётся отдельным незавершённым этапом.
